# phpLDAPadmin (github.com/leenooks/phpLDAPadmin)

Web UI for an existing LDAP directory. Laravel on FrankenPHP/Caddy, port 8080,
no database of its own.

## Deploying

Set project environment variables for your directory, then deploy:

- `LDAP_HOST` - required, e.g. `ldap.example.com`
- `LDAP_PORT` (default 389), `LDAP_CONNECTION=ldaps` for port 636
- `LDAP_USERNAME` / `LDAP_PASSWORD` - a bind DN, if the server does not allow
  anonymous reads
- `LDAP_BASE_DN` - if the server does not publish its naming contexts
- `LDAP_LOGIN_ATTR` (default `uid`), and the rest of upstream's `LDAP_*` settings

The LDAP server must be reachable from the account over the network.

Without `LDAP_HOST` the deploy fails with:

```
phpldapadmin: LDAP_HOST is not set. Set the project environment variable LDAP_HOST ...
```

## What the recipe does

- `overrides/docker-compose.yml` runs `phpldapadmin/phpldapadmin:2.3.11` on
  port 8080 with `SERVER_NAME=:8080`. The engine otherwise sets SERVER_NAME to
  the domain, which makes Caddy enable automatic HTTPS and redirect every
  request to itself.
- `ldap-check` (one-shot, runs `files/phpldapadmin-ldap-check.sh`) fails the
  deploy while `LDAP_HOST` is unset; the app starts only once it passes.
- The Laravel APP_KEY is generated by the image at container start, as
  upstream ships it; a redeploy signs everyone out.
