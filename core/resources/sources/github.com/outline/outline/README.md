# Outline (github.com/outline/outline)

Team knowledge base and wiki. One Node/Koa process serves the React editor,
the REST API and the websocket collaboration service on :3000, with PostgreSQL
for documents and Redis for queues and pub/sub.

Detection: `dockerfile` — and the container restart-looped. The repository's
root `docker-compose.yml` holds a `postgres` and a `redis` published on
127.0.0.1 and no Outline at all: it is what `yarn dev` connects to. That file
is exactly what `ComposeFileInspector::isSidecarsOnlyComposeYaml()` refuses to
run as a project (every service a known datastore, none with a `build`), so
`compose-usable` declined it and the next manifest down, `dockerfile`, took
the deploy. The build succeeded in 145s; the container then exited on every
boot, because Outline with no `DATABASE_URL`, no `REDIS_URL` and no
`SECRET_KEY` has nothing to start.

## Why the published image and not that Dockerfile

The root `Dockerfile` does not build this checkout. Its first stage is

```
ARG BASE_IMAGE=outlinewiki/outline-base
FROM ${BASE_IMAGE} AS base
```

— a floating `latest` tag — and every `COPY` in the `runner` stage takes
`build/`, `server/`, `public/`, `.sequelizerc`, `node_modules/` and
`package.json` *from that image*. The checkout contributes no compiled bytes,
so building it produces whatever `outline-base` was pushed most recently,
regardless of the commit cloned. The deploy log of the failed run shows it:
`FROM docker.io/outlinewiki/outline-base:latest@sha256:…` 55.4s, then seven
COPYs and a 62.5s export, with no yarn and no vite anywhere.

The file that builds from source is `Dockerfile.base`, and it sets
`NODE_OPTIONS="--max-old-space-size=24000"` for the vite pass. That is a 24 GB
heap inside a 2500 MB account.

So the stack runs `outlinewiki/outline`, and the *tag* is what carries the
checkout's identity. `hooks/prepare.sh` reads `version` from the checkout's
`package.json` (1.10.1 today), asks Docker Hub for the `MAJOR.MINOR` tag
(`1.10`), falls back to the exact version and then to a constant. A clone of a
1.9 branch gets 1.9, and a redeploy picks up patch releases without ever
crossing a minor — which is strictly more faithful to the checkout than
building a Dockerfile pinned to `outline-base:latest`.

## The stack

`overrides/docker-compose.yml`, a replacement rather than an override: the
file it replaces is not a project compose file at all.

- **postgres** — `postgres:16-alpine`. Not optional and not substitutable:
  Outline speaks PostgreSQL only. Its migrations `CREATE EXTENSION` for
  `uuid-ossp`, `pg_trgm`, `unaccent` and `btree_gin`; all four ship with the
  image, but the statement needs a superuser, which is why the app connects as
  the image's own `POSTGRES_USER` rather than a role created beside it.
  `PGSSLMODE=disable` is required — `server/storage/database.ts` otherwise
  fails with *"The database does not support SSL connections"*.
- **redis** — `redis:7-alpine`, `--save "" --maxmemory 96mb
  --maxmemory-policy noeviction`. Also not optional: BullMQ queues, websocket
  fan-out and `/_health` all use it. `noeviction` because evicting a BullMQ
  key silently drops queued work; no persistence because the queues rebuild
  from the database.
- **outline** — the published image, `3000:3000`, attachments on a named
  volume at `/var/lib/outline/data` (the path the image already declares
  `VOLUME` and chmods 1777 for its uid 1001 user).
- **ready** — a no-op that exits 0. See *Readiness*.

Budget inside the 2500 MB account: 1024 + 256 + 128 + 64 = 1472 MB of ceilings.

Secrets, generated by `hooks/prepare.sh` into `.env` and appended key by key
so an `.env` that already exists is added to rather than replaced:

- `SECRET_KEY` — **exactly 64 hex characters**. `server/env.ts` carries
  `@IsHexadecimal() @Length(64, 64)` on it and the constructor's validation
  runs on `process.nextTick` with `process.exit(1)`, so a wrong-shaped key is
  a restart loop, not a message.
- `UTILS_SECRET` — `@IsNotEmpty()` only; same length costs nothing.
- `POSTGRES_PASSWORD` — hex, because it is embedded in `DATABASE_URL`.

None is ever regenerated: `SECRET_KEY`'s own comment upstream is "do not
change this value once set or your users will be unable to login", and the
postgres volume outlives the checkout.

## `URL`

The one value the recipe cannot generate — the domain does not exist when the
prepare hook runs — and the one Outline needs most: every link, redirect,
websocket origin and passkey relying-party id is built from it.

The compose file ships `URL: http://localhost`. `ComposePlaceholders::
isLocalPublicUrl()` matches the key against `/(^|_)(URL|ORIGIN|ENDPOINT|
DOMAIN)$/i` — `URL` is that pattern exactly — and the value against a bare
localhost whose implied port 80 is on its allowlist, so `UserComposeStrategy`
replaces it with the account's `https://…` address before the stack starts.
`DATABASE_URL` and `REDIS_URL` match the same key pattern; their values are
not localhost, so they are left alone.

`FORCE_HTTPS` is set to `false`. At its default (`true`) `koa-force-ssl` 301s
any request arriving without `X-Forwarded-Proto` — which is every request the
loopback health probe makes — so the container would answer a redirect while
the site answered a page. `PROXY_HEADERS_TRUSTED` stays at its default `true`,
so `app.proxy` is on, `ctx.request.secure` still reads `X-Forwarded-Proto`,
and session and CSRF cookies are still issued for the https origin.

## Readiness

`docker compose up -d` runs without `--wait`, so the deploy is "finished" when
the containers have been *started*. Outline's master process runs every
pending migration against the empty database before it forks a worker that
binds 3000. `ready` is a no-op container that `depends_on` Outline being
`service_healthy`, which is what makes `up -d` block until the site answers; a
clean exit 0 is explicitly not a crash loop to `AppHealth`. It uses the redis
image so nothing extra is pulled.

Outline's healthcheck is upstream's own `/_health` (`server/main.ts`: `SELECT
1`, then a redis `PING`, then the string `OK`) with a usable interval on it
instead of the image's `--interval=1m`. `wget` is present — the Dockerfile
installs it for exactly this.

## Websockets, and a test-harness trap

Outline's editor syncs through a websocket at `/collaboration/<id>` (hocuspocus)
and uses socket.io at `/realtime` for presence. Both work: the engine's own
vhost sets `proxy_http_version 1.1`, `Upgrade $http_upgrade` and
`Connection "upgrade"`, and a handshake against the engine proxy answers **101
Switching Protocols**.

The same handshake against a `*.panelalpha.online` test domain answers **200**
— the SPA page. Those domains resolve to `eu1.withoutdns.com`, a front proxy
in front of the engine, and a packet capture of the request arriving at the
account shows `Connection: upgrade` with the `Upgrade` header gone. So on the
test harness the editor cannot sync while the REST API works perfectly, and
the difference is the front proxy, not this recipe and not the engine. Probe
the engine's own address (`--resolve <domain>:443:<engine ip>`) before
concluding anything about websockets here.

## Getting in: no OAuth provider needed

Outline has no password login, no user-creating CLI, and a `teams` row that is
normally only ever created by `accountProvisioner` on a successful SSO login.
Email sign-in (`plugins/email`) needs SMTP *and* an existing user, so it
cannot bootstrap anything.

It does have a first-run flow that needs no identity provider. `auth.config`
with no team returns `providers: []` and no `name`; `app/scenes/Login/
Login.tsx` reads that as `firstRun` and renders `WorkspaceSetup`, a form
POSTing `teamName`, `userName`, `userEmail` to `/api/installation.create`.
That endpoint (`server/routes/api/installation/installation.ts`) creates the
team with `authenticationProviders: []`, creates the user as `UserRole.Admin`
and calls `signIn()` — guarded only by `Team.count() === 0`. So a fresh deploy
is usable immediately and no OAuth application has to exist.

Two consequences, which `.panelalpha-admin-password` states in the file where
someone looks for a credential:

1. The form is open to whoever reaches the address first. Create the workspace
   before sharing the URL.
2. It works exactly once, and it issues no password. The session it hands out
   is the only way in until the admin adds a **passkey** (Settings → Profile;
   `plugins/passkeys` needs no external service, and
   `AuthenticationHelper.providersForTeam` starts offering it as soon as the
   team has one registered), or SMTP is configured for email sign-in links, or
   `OIDC_*` is configured for a real identity provider.

All three are set through the account's environment variables: the app service
reads `env_file: .env`, and `ProjectEnvironment` merges the account's
`env_vars` into that same file after the recipe has run. The generic OIDC
plugin wants `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_AUTH_URI`,
`OIDC_TOKEN_URI` and `OIDC_USERINFO_URI`, and nothing in the recipe has to
change to accept them.

## Not configured

Mail. Outline boots, the workspace is created and documents work without it,
but invites, sign-in links and notification emails need an SMTP server the
engine does not provide. S3 storage is likewise unset — attachments go to the
local volume, which is the right default for one account.
